## 2.1 语言建模的数学形式

### 2.1.1 自回归分解

一段文本 $x = (x_1, x_2, \dots, x_T)$（$x_t$ 是第 $t$ 个 token），其联合概率可以用链式法则分解为条件概率的乘积：

$$
P(x_1, \dots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_{<t})
$$

"自回归"这个名字来自时序分析：模型预测时只使用**自己之前生成的**内容作为条件。训练时我们可以一次性对所有位置并行计算（因为真值已知，这就是 Teacher Forcing）；推理时必须逐 token 生成（因为下一个 token 依赖之前生成的 token）。

### 2.1.2 交叉熵损失与困惑度

对每个位置 $t$，模型输出一个词表大小的分布 $\hat p_t \in \mathbb{R}^{V}$（V 是词表大小）。训练损失是所有位置的交叉熵平均：

$$
\mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T} \log \hat p_t(x_t)
$$

其中 $\hat p_t(x_t)$ 是模型给真实 token $x_t$ 赋予的概率。等价地，用 softmax 后的 logits 写：设 $z_t = \text{logits}_t \in \mathbb{R}^{V}$，则

$$
\mathcal{L} = \frac{1}{T}\sum_{t=1}^{T} \left[ -z_t[x_t] + \log\sum_{v=1}^{V} e^{z_t[v]} \right]
$$

**困惑度（Perplexity, PPL）**是衡量语言模型的经典指标：

$$
\text{PPL} = \exp(\mathcal{L})
$$

直觉：PPL = 模型在每个位置平均"犹豫"于多少个候选 token。PPL = 10 意味着平均每次预测要从 10 个候选里选。MiniMind 预训练结束时的 loss 约 4~5，即 PPL 约 55~150——听起来很大，但注意语言模型预测的是**单个 token**（比如下一个词是"蓝"还是"红"的 6400 选 1），PPL 50 左右在小模型上是正常水平。

> ⚠️ PPL 只能在**同一个 tokenizer** 下比较。换分词器后 token 粒度变了，PPL 不可比（这就是 README 中提到的 BPB 指标的动机，详见第 3 章）。

### 2.1.3 为什么 LLM 用交叉熵而不是"准确率"做损失

准确率（argmax 是否等于真值）不可导，且梯度为 0（离散的跳变）；交叉熵对 logits 的梯度是

$$
\frac{\partial \mathcal{L}}{\partial z_t[v]} = \hat p_t(v) - \mathbf{1}[v = x_t]
$$

——即"预测概率 − 真值指示"。真值 token 的概率每差 1 个百分点，梯度就推着模型向它靠近 1 个百分点。这个形式干净、可导、且对错误程度敏感（概率越低错得越狠），是语言建模的标配。

## 2.2 Transformer 组件快复习（LLM 视角）

### 2.2.1 缩放点积注意力

$$
\text{Attn}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right) V
$$

除以 $\sqrt{d_k}$ 的原因：$QK^\top$ 各项是 $d_k$ 个独立随机变量之和，方差随 $d_k$ 线性增长；除以 $\sqrt{d_k}$ 把方差拉回 1，避免 softmax 进入饱和区（梯度消失）。

LLM 中使用的是**因果注意力（causal attention）**：位置 $t$ 只能看到 $t$ 及之前的位置。实现上通过把上三角矩阵置为 $-\infty$（mask）再 softmax。

MiniMind 中的对应代码（`model_minimind.py`）：

```python
scores = (xq @ xk.transpose(-2, -1)) / math.sqrt(self.head_dim)
if self.is_causal:
    scores[:, :, :, -seq_len:] += torch.full((seq_len, seq_len), float("-inf"), device=scores.device).triu(1)
output = F.softmax(scores.float(), dim=-1) @ xv
```

逐行解读：
- 第 1 行：点积相似度 + 缩放；
- 第 2~3 行：把上三角（不含对角线）填为 $-\infty$，softmax 后这些位置的权重为 0；
- 第 4 行：`scores.float()` 转 float32 计算 softmax——**为什么？** 因为 bf16/fp16 下指数运算精度损失大，这是训练稳定性上的常见工程细节。

> `triu(1)` 表示取主对角线之上的部分（k=1 偏移），保证位置 $t$ 能看到自己（对角线保留）。

### 2.2.2 LayerNorm → RMSNorm

原始 LayerNorm 对每个 token 的隐藏向量做归一化，再仿射变换：

$$
\text{LayerNorm}(x) = \gamma \cdot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta
$$

其中 $\mu, \sigma$ 是该 token 向量维度上的均值和标准差，$\gamma, \beta$ 是可学习参数。

**RMSNorm**（Zhang & Sennrich, 2019）去掉了均值中心化，只做缩放：

$$
\text{RMSNorm}(x) = \gamma \cdot \frac{x}{\sqrt{\text{RMS}(x)^2 + \epsilon}}, \quad \text{RMS}(x) = \sqrt{\frac{1}{d}\sum_{i=1}^{d} x_i^2}
$$

为什么可以去掉均值？因为 Transformer 中 LayerNorm 的均值中心化主要是为了配合残差结构稳定数值，而 RMSNorm 的实证效果与 LayerNorm 几乎一致，但省去了计算均值的开销（约提速 10~30%）。现代 LLM（Llama、Qwen、MiniMind）几乎全部使用 RMSNorm。

MiniMind 的实现（`model_minimind.py` 第 50~60 行）：

```python
class RMSNorm(torch.nn.Module):
    def __init__(self, dim: int, eps: float = 1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))   # 可学习的缩放因子 γ

    def norm(self, x):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

    def forward(self, x):
        return (self.weight * self.norm(x.float())).type_as(x)
```

`torch.rsqrt` 是"平方根倒数"，一条指令完成 $\frac{1}{\sqrt{\cdot}}$ 计算，比先算 sqrt 再除更快更稳。

### 2.2.3 残差连接与 Pre-Norm

Transformer 每个子层都带残差连接：

$$
x = x + \text{Sublayer}(\text{Norm}(x))
$$

这是 **Pre-Norm** 结构（先归一化再进子层）。相对 Post-Norm（先子层再归一化），Pre-Norm 的梯度更稳定，深层网络更容易训练——代价是效果略逊（现代 LLM 通过加大数据量弥补）。MiniMind 的 `MiniMindBlock`（第 178~194 行）正是 Pre-Norm：

```python
residual = hidden_states
hidden_states, present_key_value = self.self_attn(
    self.input_layernorm(hidden_states), ...)   # 先 Norm 再 Attn
hidden_states += residual                        # 残差相加
hidden_states = hidden_states + self.mlp(self.post_attention_layernorm(hidden_states))
```

### 2.2.4 位置编码：从绝对到旋转

Transformer 没有循环结构，位置信息必须显式注入。演进路线：

1. **绝对位置编码**（原版 Transformer）：加一个位置向量。缺点：长度外推能力差，位置向量本身要学。
2. **RoPE 旋转位置编码**（Rotary Position Embedding, Su et al. 2021）：把位置信息以"旋转矩阵"的方式乘进 Q、K。关键性质：
   - 相对位置由内积自然产生：$\langle R_m q, R_n k \rangle$ 只依赖 $m-n$；
   - **长度外推友好**：位置通过连续函数（三角函数）编码，训练时未见过的位置也能算出来。

RoPE 的数学：对每个维度对 $(2i, 2i+1)$，用角度 $\theta_i = 1/\text{rope\_theta}^{2i/d}$ 旋转：

$$
R(m) = \begin{pmatrix} \cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i \end{pmatrix}
$$

MiniMind 的实现细节在第 4 章精读（`precompute_freqs_cis` + `apply_rotary_pos_emb`），这里只需要建立"位置编码是旋转"的直觉。注意 `rope_theta = 1e6` 是个超参数：它控制频率基底，影响长距离依赖建模，Qwen 系模型普遍用 1e6 以上。

### 2.2.5 SwiGLU 激活

原始 FFN：$\text{FFN}(x) = \text{ReLU}(xW_1 + b_1) W_2 + b_2$

SwiGLU 门控版本：

$$
\text{FFN}_{\text{SwiGLU}}(x) = (\text{Swish}(xW_g) \odot (xW_u)) W_d
$$

其中 $\text{Swish}(z) = z \cdot \sigma(z)$，$\odot$ 是逐元素乘。三个权重矩阵 $W_g$（gate）、$W_u$（up）、$W_d$（down）——这就是为什么 MiniMind 的 FFN 有三个 Linear（第 140~142 行）：

```python
self.gate_proj = nn.Linear(config.hidden_size, intermediate_size, bias=False)
self.down_proj = nn.Linear(intermediate_size, config.hidden_size, bias=False)
self.up_proj   = nn.Linear(config.hidden_size, intermediate_size, bias=False)
```

> SwiGLU 相比 ReLU 的优势：门控机制让信息流更灵活，实证效果更好；代价是参数多 50%（3 个矩阵 vs 2 个）。注意 `intermediate_size` 的取值——MiniMind 用了一个有趣的公式：`math.ceil(hidden_size * math.pi / 64) * 64`，768×π/64≈37.7 → ceil 到 38 → ×64 = **2432**。取 π 是为了让中间维度不被"对齐到 4 的倍数"这类惯例绑架，保证参数组合的多样性，这是作者的有意设计。

### 2.2.6 GQA 分组查询注意力

标准 MHA（多头注意力）每个头一套 K、V 投影；GQA（Grouped-Query Attention）让**多个 Q 头共享一组 K、V**：

- MiniMind 配置：8 个 Q 头、4 个 KV 头 → 每 2 个 Q 头共享 1 组 KV（`n_rep = 8/4 = 2`）
- 效果：KV Cache 显存减半（4/8），推理吞吐提升，效果损失很小（Ainslie et al. 2023）

对应代码（第 94~103 行）：`k_proj` 输出维度是 `num_key_value_heads * head_dim`（4×96），而非 `num_attention_heads * head_dim`（8×96）。KV 在进入注意力前通过 `repeat_kv` 复制（第 86~89 行）。

## 2.3 训练工程基础

### 2.3.1 梯度累积（Gradient Accumulation）

显存有限，batch 太大放不下。解决：**小 batch 前向反向多次，梯度累加后统一更新**。

```
等价关系：有效 batch size = batch_size × accumulation_steps
```

MiniMind 实现（`train_pretrain.py`）：

```python
loss = loss / args.accumulation_steps   # 先除以累积步数（平均化）
scaler.scale(loss).backward()           # 每步都反向
if step % args.accumulation_steps == 0: # 每 N 步更新一次
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), args.grad_clip)
    scaler.step(optimizer)
    scaler.update()
    optimizer.zero_grad(set_to_none=True)
```

注意 `loss / accumulation_steps` 这行：因为 PyTorch 梯度是**累加**的，若不对 loss 除以 N，等效 batch 的梯度会被放大 N 倍，学习率需要等比缩小。

### 2.3.2 混合精度训练（AMP）

核心思想：**前向/反向用低精度（fp16/bf16）加速，主权重和优化器状态保持 fp32 精度**。

- **fp16**：范围窄，容易上溢/下溢，需要 `GradScaler` 动态缩放 loss（先乘大数再反传，防止梯度下溢为 0）。
- **bf16**（bfloat16）：指数位与 fp32 相同，范围够大**无需 GradScaler**，但尾数位少（精度略低）。现代 GPU（A100/H100/4090 等）推荐 bf16。

MiniMind 中：

```python
dtype = torch.bfloat16 if args.dtype == "bfloat16" else torch.float16
autocast_ctx = nullcontext() if device_type == "cpu" else torch.cuda.amp.autocast(dtype=dtype)
scaler = torch.cuda.amp.GradScaler(enabled=(args.dtype == 'float16'))  # 仅 fp16 启用
```

三个细节值得注意：
1. CPU 上直接 `nullcontext()`，不做混合精度；
2. `GradScaler(enabled=...)`：bf16 时禁用缩放器；
3. **权重保存为 fp16**：`torch.save({k: v.half().cpu() for k, v in state_dict.items()}, ckp)`——模型权重 fp16 存储，加载时 `.half()` 推理。训练时模型参数其实还是 fp32（PyTorch 默认），AMP 只在计算时自动降精度。

### 2.3.3 学习率调度：余弦退火

MiniMind 使用带下限的余弦退火（`trainer_utils.py` 第 40~41 行）：

```python
def get_lr(current_step, total_steps, lr):
    return lr * (0.1 + 0.45 * (1 + math.cos(math.pi * current_step / total_steps)))
```

- $t=0$：$\text{lr} = lr \times (0.1 + 0.9) = lr$（初始学习率，如 5e-4）
- $t=T$：$\text{lr} = lr \times 0.1$（衰减到初始的 10%，不归零）

```text
lr
 │╲
 │  ╲
 │    ╲__________   ← 平滑衰减，末期保持 0.1 倍下限
 └─────────────────→ step
```

为什么余弦退火？相比恒定学习率，它在训练前期保持较高学习率快速下降，后期平滑收敛，是 LLM 训练的业界标配（GPT-3 即用）。**保留 0.1 下限**是为了防止学习率归零后无法从局部最优点继续微调（对后续 SFT/RL 阶段衔接重要）。

### 2.3.4 梯度裁剪

`clip_grad_norm_(model.parameters(), 1.0)`：把所有参数的梯度整体缩放到范数不超过 1.0。防止个别 batch 的异常梯度把参数推出稳定区——LLM 训练中 loss 尖峰（loss spike）的常见解药之一。

### 2.3.5 显存估算（back-of-envelope）

64M 参数的模型，训练显存大致为：

| 项目 | 显存占用 | 说明 |
|------|----------|------|
| 模型参数（fp32） | 64M × 4B = 256 MB | 主权重 |
| Adam 优化器状态 | 64M × 8B = 512 MB | m 和 v 各一份 fp32 |
| 梯度（fp32） | 64M × 4B = 256 MB | |
| 激活值 | 与 batch×seq_len 成正比 | 前向中间结果，通常数倍于参数 |
| **合计（训练）** | **约 1.5~3 GB** | 24 GB 显卡绰绰有余 |

推理则只需参数 + KV Cache：bf16 权重 128 MB + KV Cache（4 头 × 96 维 × 2 (K+V) × 2 字节 × seq_len × 层数 × batch）。这也是为什么 64M 模型能在任何显卡甚至 CPU 上跑。

> 一个有意思的验证：`init_model` 里打印的 `Model Params: 64.xxM` 就是 `sum(p.numel())` 除以 1e6 的结果（第 4 章会手动重算一遍验证）。

## 2.4 logits 与标签的对齐（LLM 特有的坑）

交叉熵需要 logits 和 labels 对齐。MiniMind 的 `MiniMindForCausalLM.forward`（第 250~252 行）：

```python
x, y = logits[..., :-1, :].contiguous(), labels[..., 1:].contiguous()
loss = F.cross_entropy(x.view(-1, x.size(-1)), y.view(-1), ignore_index=-100)
```

为什么是 `[:-1]` 和 `[1:]`？

- 位置 $t$ 的 logits 预测的是**位置 $t+1$** 的 token（第 $t$ 个 token 是条件）；
- 因此 logits 要丢掉最后一个位置（它没有"下一个"可预测），labels 要丢掉第一个位置（它没有"上一个"条件）。

```text
input_ids:  [A] [B] [C] [D]
logits:     P(→B) P(→C) P(→D)   ← 只保留前 3 个
labels:     [B] [C] [D]          ← 去掉开头的 A
```

`ignore_index=-100`：PyTorch 交叉熵遇到 -100 标签直接跳过该位置——这就是 padding 位置和"不需要学习"位置（如 SFT 中的 user 内容）的处理方式（第 6 章重点）。

## 2.5 本章小结

- 语言建模 = 自回归 + 交叉熵；PPL 只在同 tokenizer 下可比。
- 现代 LLM 的"新标配"：RMSNorm（省去均值中心化）、Pre-Norm（训练稳定）、SwiGLU（门控 FFN）、RoPE（旋转位置编码、可外推）、GQA（KV 共享省显存）。
- 训练工程四件套：梯度累积（等效大 batch）、AMP（bf16 无 scaler / fp16 需 scaler）、余弦退火（带下限）、梯度裁剪。
- logits/labels 对齐：`[:-1]` vs `[1:]`，`ignore_index=-100` 是 LLM 训练的核心套路。
