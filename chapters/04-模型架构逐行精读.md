## 4.1 架构总览

```text
input_ids (B, T)
   │
   ▼
┌───────────────────────────────┐
│ Embedding (6400 → 768)        │  ← 与 lm_head 权重共享（tie）
├───────────────────────────────┤
│ Dropout                       │
├───────────────────────────────┤
│ MiniMindBlock × 8             │
│  ┌─────────────────────────┐  │
│  │ RMSNorm → Attention     │  │  ← GQA 8Q/4KV + RoPE + QK-Norm
│  │ ＋ 残差                  │  │
│  │ RMSNorm → FFN (SwiGLU)  │  │  ← Dense 或 MoE(4 experts/top-1)
│  │ ＋ 残差                  │  │
│  └─────────────────────────┘  │
├───────────────────────────────┤
│ RMSNorm (最终)                │
├───────────────────────────────┤
│ lm_head (768 → 6400)          │  ← 与 Embedding 共享权重
└───────────────────────────────┘
   │
   ▼
logits (B, T, 6400) → softmax → 下一个 token 概率
```

这是标准的 **Decoder-Only Pre-Norm Transformer**，配置对齐 Qwen3 生态（这是为了后续能无缝转换到 transformers/llama.cpp/vllm 等生态）。

## 4.3 逐模块精读

### 4.3.1 RMSNorm（第 50~60 行）

```python
class RMSNorm(torch.nn.Module):
    def __init__(self, dim: int, eps: float = 1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def norm(self, x):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

    def forward(self, x):
        return (self.weight * self.norm(x.float())).type_as(x)
```

实现要点：

1. `x.pow(2).mean(-1, keepdim=True)`：对最后一维（隐藏维度）求均方，`keepdim=True` 保持广播形状；
2. `torch.rsqrt`：$\frac{1}{\sqrt{x}}$，比 `1 / torch.sqrt(x)` 少一次除法、数值更稳；
3. **`x.float()` 先升精度再归一化，最后 `.type_as(x)` 转回原精度**——bf16 下做平方/开方误差大，这是工程上防精度的标准写法（与 Attention 里的 softmax float() 同理）；
4. 参数只有 `weight`（缩放因子），没有 bias、没有均值项——这正是 RMSNorm 比 LayerNorm 省的地方。

### 4.3.2 RoPE：旋转位置编码（第 62~84 行）

**① 频率预计算 `precompute_freqs_cis`**

```python
def precompute_freqs_cis(dim: int, end: int = int(32 * 1024), rope_base: float = 1e6, rope_scaling: dict = None):
    freqs, attn_factor = 1.0 / (rope_base ** (torch.arange(0, dim, 2)[: (dim // 2)].float() / dim)), 1.0
```

频率公式：$\theta_i = \frac{1}{\text{rope\_base}^{2i/d}}$，其中 $i = 0, 1, \dots, d/2-1$ 遍历**维度对**。

- `torch.arange(0, dim, 2)`：取偶数下标 0, 2, 4, ..., dim-2；
- `rope_base ** (idx/dim)`：指数衰减的频率——**低频（小 i）负责长距离、高频（大 i）负责短距离**，与傅里叶分解的直觉一致。

```python
    t = torch.arange(end, device=freqs.device)
    freqs = torch.outer(t, freqs).float()
    freqs_cos = torch.cat([torch.cos(freqs), torch.cos(freqs)], dim=-1) * attn_factor
    freqs_sin = torch.cat([torch.sin(freqs), torch.sin(freqs)], dim=-1) * attn_factor
    return freqs_cos, freqs_sin
```

- `torch.outer(t, freqs)`：位置 × 频率的二维表，形状 `(end, dim/2)`，第 $m$ 行就是位置 $m$ 的全部角度 $m\theta_i$；
- `cat` 两次是把 `dim/2` 维复制成 `dim` 维——因为旋转是对**相邻维度对**做的，复制后 `cos[m]` 的第 `2i`、`2i+1` 位相同，正好匹配 `rotate_half` 的配对方式；
- 返回值是查表（lookup table）：形状 `(end, dim)` 的 cos/sin 表。**端到端预计算，推理时 O(1) 取切片**，这是高性能实现的标准做法。

**YaRN 分支**（第 64~73 行，推理外推用）：

```python
if rope_scaling is not None:
    orig_max, factor, beta_fast, beta_slow, attn_factor = (...)
    if end / orig_max > 1.0:   # 只有超出原训练长度才干预
        inv_dim = lambda b: (dim * math.log(orig_max / (b * 2 * math.pi))) / (2 * math.log(rope_base))
        low, high = max(math.floor(inv_dim(beta_fast)), 0), min(math.ceil(inv_dim(beta_slow)), dim // 2 - 1)
        ramp = torch.clamp((torch.arange(dim // 2).float() - low) / max(high - low, 0.001), 0, 1)
        freqs = freqs * (1 - ramp + ramp / factor)   # f'(i) = f(i)·((1-γ) + γ/s)
```

- 核心思想：**只对低频维度（负责长距离）拉长频率**，高频维度（短距离）保持不动——因为长距离位置信息主要由低频分量携带；
- `inv_dim` 求出"哪些维度是低频"（beta_fast/beta_slow 界定频段边界）；
- `ramp` 是 0→1 的线性过渡带（γ 系数），避免频率突变导致训练分布断裂；
- 效果：训练 2048 长度的模型，推理时可外推到 8192+（第 7 章实验验证）。注意这是"缓解位置编码问题"，不是"凭空获得长文本能力"。

**② 旋转应用 `apply_rotary_pos_emb`**（第 80~84 行）

```python
def apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1):
    def rotate_half(x): return torch.cat((-x[..., x.shape[-1] // 2:], x[..., : x.shape[-1] // 2]), dim=-1)
    q_embed = ((q * cos.unsqueeze(unsqueeze_dim)) + (rotate_half(q) * sin.unsqueeze(unsqueeze_dim))).to(q.dtype)
    k_embed = ((k * cos.unsqueeze(unsqueeze_dim)) + (rotate_half(k) * sin.unsqueeze(unsqueeze_dim))).to(k.dtype)
    return q_embed, k_embed
```

数学上，对维度对 $(x_{2i}, x_{2i+1})$ 施加旋转：

$$
\begin{pmatrix} x'_{2i} \\ x'_{2i+1} \end{pmatrix} = \begin{pmatrix} \cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i \end{pmatrix} \begin{pmatrix} x_{2i} \\ x_{2i+1} \end{pmatrix}
$$

代码中的技巧：`rotate_half(x)` 把后一半挪到前一半并取负，配合逐元素乘加，一次完成旋转——`x * cos + rotate_half(x) * sin` 正是旋转矩阵乘法的等价形式（不需要真的构造矩阵）。

### 4.3.3 Attention：GQA + QK-Norm + KV Cache（第 91~134 行）

**初始化**（第 94~109 行）：

```python
self.n_local_heads = config.num_attention_heads        # 8
self.n_local_kv_heads = self.num_key_value_heads       # 4
self.n_rep = self.n_local_heads // self.n_local_kv_heads  # 2
self.head_dim = config.head_dim                        # 96
self.q_proj = nn.Linear(config.hidden_size, config.num_attention_heads * self.head_dim, bias=False)  # 768→768
self.k_proj = nn.Linear(config.hidden_size, self.num_key_value_heads * self.head_dim, bias=False)    # 768→384
self.v_proj = nn.Linear(config.hidden_size, self.num_key_value_heads * self.head_dim, bias=False)    # 768→384
self.o_proj = nn.Linear(config.num_attention_heads * self.head_dim, config.hidden_size, bias=False)  # 768→768
self.q_norm = RMSNorm(self.head_dim, eps=config.rms_norm_eps)
self.k_norm = RMSNorm(self.head_dim, eps=config.rms_norm_eps)
```

- **GQA 的实现**：K、V 投影只输出 4 头的量（384 维），Q 是 8 头（768 维）；4 个 KV 头被 8 个 Q 头共享（`n_rep=2`）；
- **QK-Norm**（q_norm/k_norm）：对 Q、K 的每头 96 维再做 RMSNorm。这是 Qwen3/Llama 3.1 之后的趋势——**在 bf16 低精度下稳定注意力分数**，防止数值漂移导致训练发散；推理 KV Cache 存的是归一化后的 K，外推时更稳；
- 所有投影 `bias=False`：现代 LLM 的共识（省参数、省显存，效果无损）。

**前向**（第 111~134 行）：

```python
xq, xk, xv = self.q_proj(x), self.k_proj(x), self.v_proj(x)
xq = xq.view(bsz, seq_len, self.n_local_heads, self.head_dim)
xk = xk.view(bsz, seq_len, self.n_local_kv_heads, self.head_dim)
xv = xv.view(bsz, seq_len, self.n_local_kv_heads, self.head_dim)
xq, xk = self.q_norm(xq), self.k_norm(xk)
xq, xk = apply_rotary_pos_emb(xq, xk, cos, sin)
```

形状演化（以 B=2, T=340 为例）：

```text
x:        (2, 340, 768)
xq:       (2, 340, 8, 96)     ← Q 8 头
xk/xv:    (2, 340, 4, 96)     ← K/V 4 头（GQA）
```

**KV Cache**（第 120~123 行）：

```python
if past_key_value is not None:
    xk = torch.cat([past_key_value[0], xk], dim=1)   # 沿序列维拼接历史 K
    xv = torch.cat([past_key_value[1], xv], dim=1)
past_kv = (xk, xv) if use_cache else None
```

- 推理逐 token 生成时，**历史 K/V 无需重算**，缓存后每步只算新 token 的 K/V 再拼接——把每步计算量从 O(T²) 降到 O(T)；
- `dim=1` 是序列维：`(B, past_len+1, heads, dim)`；
- `use_cache=False`（训练时）则不保存，返回 None。

**重复 KV + 注意力计算**（第 124~131 行）：

```python
xq, xk, xv = (xq.transpose(1, 2),
              repeat_kv(xk, self.n_rep).transpose(1, 2),
              repeat_kv(xv, self.n_rep).transpose(1, 2))
if self.flash and (seq_len > 1) and (not self.is_causal or past_key_value is None) and (attention_mask is None or torch.all(attention_mask == 1)):
    output = F.scaled_dot_product_attention(xq, xk, xv, dropout_p=..., is_causal=self.is_causal)
else:
    scores = (xq @ xk.transpose(-2, -1)) / math.sqrt(self.head_dim)
    if self.is_causal:
        scores[:, :, :, -seq_len:] += torch.full((seq_len, seq_len), float("-inf"), device=scores.device).triu(1)
    if attention_mask is not None:
        scores += (1.0 - attention_mask.unsqueeze(1).unsqueeze(2)) * -1e9
    output = self.attn_dropout(F.softmax(scores.float(), dim=-1).type_as(xq)) @ xv
```

- `repeat_kv`（第 86~89 行）：4 个 KV 头沿新轴复制成 8 份，再 reshape——注意用 `expand`（不拷贝内存）+ `reshape`（必要时才拷贝），高效实现 GQA；
- **Flash Attention 分支**：PyTorch 2.x 内置 `scaled_dot_product_attention` 自动用 FlashAttention 内核（显存 O(1)、速度快数倍）。触发条件苛刻，注意 `seq_len > 1` 且推理单 token 时不触发（此时退化为朴素实现 + KV Cache）；
- 朴素实现里 mask 用 `-inf`（`triu(1)` 上三角置 -inf），padding mask 用 `-1e9`（防 NaN 传播）——两种负无穷的区分是工程细节；
- **`scores[:, :, :, -seq_len:]`**：只给"新来的 seq_len 个位置"加因果掩码——配合 KV Cache，历史位置不受影响。

**输出**（第 132~133 行）：

```python
output = output.transpose(1, 2).reshape(bsz, seq_len, -1)   # (B, heads, T, d) → (B, T, 8×96)
output = self.resid_dropout(self.o_proj(output))
```

### 4.3.4 FeedForward：SwiGLU（第 136~146 行）

```python
class FeedForward(nn.Module):
    def __init__(self, config, intermediate_size=None):
        intermediate_size = intermediate_size or config.intermediate_size   # 2432
        self.gate_proj = nn.Linear(config.hidden_size, intermediate_size, bias=False)
        self.down_proj = nn.Linear(intermediate_size, config.hidden_size, bias=False)
        self.up_proj = nn.Linear(config.hidden_size, intermediate_size, bias=False)
        self.act_fn = ACT2FN[config.hidden_act]   # 'silu' → SiLU（即 Swish）

    def forward(self, x):
        return self.down_proj(self.act_fn(self.gate_proj(x)) * self.up_proj(x))
```

SwiGLU 公式对应：$\text{down}(\sigma(\text{gate}(x)) \odot \text{up}(x))$。`ACT2FN` 来自 transformers，`'silu'` 即 SiLU/Swish 激活 $\sigma(z) \cdot z$。

### 4.3.5 MOEFeedForward：稀疏专家（第 148~176 行）

MoE（Mixture of Experts）的核心思想：**把 FFN 复制成 N 份"专家"，每个 token 只激活其中 k 个**——参数量大、计算量小（只算被激活的专家）。

```python
class MOEFeedForward(nn.Module):
    def __init__(self, config):
        self.gate = nn.Linear(config.hidden_size, config.num_experts, bias=False)   # 768→4 路由器
        self.experts = nn.ModuleList([FeedForward(config, config.moe_intermediate_size) for _ in range(config.num_experts)])

    def forward(self, x):
        batch_size, seq_len, hidden_dim = x.shape
        x_flat = x.view(-1, hidden_dim)                          # (B*T, 768) 展平所有 token
        scores = F.softmax(self.gate(x_flat), dim=-1)            # 每个 token 对 4 个专家的偏好
        topk_weight, topk_idx = torch.topk(scores, k=self.config.num_experts_per_tok, dim=-1, sorted=False)
        if self.config.norm_topk_prob:
            topk_weight = topk_weight / (topk_weight.sum(dim=-1, keepdim=True) + 1e-20)  # top-1 时无效果；top-k>1 时归一化
        y = torch.zeros_like(x_flat)
        for i, expert in enumerate(self.experts):                # 逐专家计算（朴素实现）
            mask = (topk_idx == i)
            if mask.any():
                token_idx = mask.any(dim=-1).nonzero().flatten()
                weight = topk_weight[mask].view(-1, 1)
                y.index_add_(0, token_idx, (expert(x_flat[token_idx]) * weight).to(y.dtype))
            elif self.training:                                  # 防止死专家：让优化器把该专家参数"留痕"
                y[0, 0] += 0 * sum(p.sum() for p in expert.parameters())
        if self.training and self.config.router_aux_loss_coef > 0:
            load = F.one_hot(topk_idx, self.config.num_experts).float().mean(0)          # 各专家被选频率
            self.aux_loss = (load * scores.mean(0)).sum() * self.config.num_experts * self.config.router_aux_loss_coef
        else:
            self.aux_loss = scores.new_zeros(1).squeeze()
        return y.view(batch_size, seq_len, hidden_dim)
```

逐段解读：

1. **路由**：`gate` 输出 4 个分数 → softmax → `topk(1)` 选得分最高的专家（top-1）；
2. **分派与聚合**：`mask` 标记被派到专家 i 的 token，`index_add_` 把专家输出加权累加回原位置；
3. **负载均衡损失（aux loss）**：`load` 是专家实际负载分布，`scores.mean(0)` 是路由概率均值。若所有 token 都涌向专家 0，`load·scores` 乘积会高——**惩罚"路由坍缩"**，鼓励 token 均匀分布到各专家。系数 `router_aux_loss_coef=5e-4` 很小，不干扰主损失；
4. **死专家保护**：`elif self.training: y[0,0] += 0 * sum(...)`——把专家参数的梯度以 0 倍挂到计算图上，确保没被选中的专家在 DDP/AMP 下仍然得到梯度同步（防止参数"烂在角落里"）。这行代码看似诡异，实为分布式训练的经典技巧。

> 注意 MoE 版本的参数量与激活量：总参数 = dense 部分 + 4×专家参数；激活参数 = dense 部分 + 1×专家参数（top-1）。README 中 `198M-A64M` 的 A 就是 active 的缩写。训练时 token 按专家分桶计算，朴素实现下 kernel 启停开销大，所以 MoE 训练不一定比 Dense 快（README 有专门讨论）。

### 4.3.6 MiniMindBlock：残差 + Pre-Norm（第 178~194 行）

```python
class MiniMindBlock(nn.Module):
    def __init__(self, layer_id, config):
        self.self_attn = Attention(config)
        self.input_layernorm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
        self.post_attention_layernorm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
        self.mlp = FeedForward(config) if not config.use_moe else MOEFeedForward(config)

    def forward(self, hidden_states, position_embeddings, past_key_value=None, use_cache=False, attention_mask=None):
        residual = hidden_states
        hidden_states, present_key_value = self.self_attn(
            self.input_layernorm(hidden_states), position_embeddings, past_key_value, use_cache, attention_mask)
        hidden_states += residual
        hidden_states = hidden_states + self.mlp(self.post_attention_layernorm(hidden_states))
        return hidden_states, present_key_value
```

标准 Pre-Norm 残差块。注意 `position_embeddings` 是**跨层共享**的（每层的 QK 用同一张 RoPE 表，RoPE 不需要学习参数）。

### 4.3.7 MiniMindModel：主干（第 196~232 行）

```python
class MiniMindModel(nn.Module):
    def __init__(self, config):
        self.embed_tokens = nn.Embedding(config.vocab_size, config.hidden_size)
        self.layers = nn.ModuleList([MiniMindBlock(l, config) for l in range(self.num_hidden_layers)])
        self.norm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
        freqs_cos, freqs_sin = precompute_freqs_cis(dim=config.head_dim, end=config.max_position_embeddings, ...)
        self.register_buffer("freqs_cos", freqs_cos, persistent=False)   # 非持久 buffer：不进入 state_dict
        self.register_buffer("freqs_sin", freqs_sin, persistent=False)
```

**前向的隐藏细节**：

```python
start_pos = past_key_values[0][0].shape[1] if past_key_values[0] is not None else 0   # 推理续写起点
...
position_embeddings = (self.freqs_cos[start_pos:start_pos + seq_length],
                       self.freqs_sin[start_pos:start_pos + seq_length])               # 查表切片
```

- RoPE 表长度 `max_position_embeddings=32768`——**预计算一张 32768 行的表**，训练时只取前 max_seq_len 行，推理时可取到 32768 行（不训练也能用，只是外推位置没有见过）；
- `register_buffer(..., persistent=False)`：RoPE 表不参与保存/加载（可推导的常量），模型文件更小；
- 第 216~218 行有一个特殊处理：`if self.freqs_cos[0, 0] == 0:` 重新计算——处理 transformers≥5.x 的 meta-device 初始化（权重加载到 meta 设备时 buffer 会丢失）。这是**兼容性补丁**，日常使用不会触发；
- MoE 的 `aux_loss` 在主干末尾汇总（第 231 行）：`sum([l.mlp.aux_loss for l in self.layers if isinstance(l.mlp, MOEFeedForward)], ...)`。

### 4.3.8 MiniMindForCausalLM：外壳与损失（第 234~253 行）

```python
class MiniMindForCausalLM(PreTrainedModel, GenerationMixin):
    config_class = MiniMindConfig
    _tied_weights_keys = {"lm_head.weight": "model.embed_tokens.weight"}
    def __init__(self, config=None):
        self.config = config or MiniMindConfig()
        super().__init__(self.config)
        self.model = MiniMindModel(self.config)
        self.lm_head = nn.Linear(self.config.hidden_size, self.config.vocab_size, bias=False)
        if self.config.tie_word_embeddings:
            self.model.embed_tokens.weight = self.lm_head.weight   # 权重共享（同一 Parameter 对象）
        self.post_init()
```

- **Tied Embeddings（权重共享）**：`embed_tokens.weight` 和 `lm_head.weight` 指向同一个 Parameter——节省 `6400×768 = 4.9M` 参数（约 7.7%）。**为什么可行？** 输入 token 与输出 token 来自同一分布，共享词向量在中小模型上被反复验证有效（GPT-2、T5 等都用）。代价是输出层失去了独立学习的自由度；
- 继承 `GenerationMixin`：获得 transformers 的 `generate` 接口能力。注意 MiniMind **自己重写了 `generate`**（第 257~288 行），签名与 HF 版本不完全相同——第 7 章逐行讲。

**前向与损失**：

```python
def forward(self, input_ids, attention_mask=None, past_key_values=None, use_cache=False, logits_to_keep=0, labels=None, **kwargs):
    hidden_states, past_key_values, aux_loss = self.model(input_ids, attention_mask, past_key_values, use_cache, **kwargs)
    slice_indices = slice(-logits_to_keep, None) if isinstance(logits_to_keep, int) else logits_to_keep
    logits = self.lm_head(hidden_states[:, slice_indices, :])
    loss = None
    if labels is not None:
        x, y = logits[..., :-1, :].contiguous(), labels[..., 1:].contiguous()
        loss = F.cross_entropy(x.view(-1, x.size(-1)), y.view(-1), ignore_index=-100)
    return MoeCausalLMOutputWithPast(loss=loss, aux_loss=aux_loss, logits=logits, ...)
```

- `logits_to_keep`：RL 阶段只需要最后几个位置的 logits（第 10 章），避免算全序列省显存——`slice(-k, None)` 只保留末尾 k 个位置；
- 第 2 章的 `[:-1]` vs `[1:]` 对齐在这里落地；
- 返回类型 `MoeCausalLMOutputWithPast`：transformers 标准输出容器，兼容生态。

## 4.4 参数量推导：64M 从何而来

逐项手算（与 `get_model_params` 打印的 `Model Params: 63.91M` 对照）：

| 模块 | 公式 | 参数量 |
|------|------|--------|
| Embedding（与 lm_head 共享） | 6400 × 768 | 4,915,200 |
| 每层 Attention：q_proj | 768 × 768 | 589,824 |
| k_proj | 768 × (4×96) | 294,912 |
| v_proj | 768 × (4×96) | 294,912 |
| o_proj | 768 × 768 | 589,824 |
| q_norm + k_norm | 96 + 96 | 192 |
| 每层 FFN：gate/up/down | 768×2432 × 3 | 5,603,328 |
| 每层 RMSNorm ×2 | 768 × 2 | 1,536 |
| **每层合计** | | **7,374,528** |
| 8 层合计 | × 8 | 58,996,224 |
| 最终 RMSNorm | 768 | 768 |
| **总计** | | **63,912,192 ≈ 63.9M** |

几个关键结论：

1. **词表占 4.9M（7.7%）**——这正是第 3 章说"6400 词表是刻意精简"的数字证据；若用 Qwen2 的 151643 词表，仅 embedding 就是 116M，超过整个 MiniMind；
2. **FFN 占大头**：每层 5.6M / 7.4M ≈ 76%，注意力只占 ~24%——Transformer 的参数结构就是如此，这解释了为什么 MoE（替换 FFN）能显著扩大参数量；
3. `intermediate_size = ceil(768×π/64)×64 = 2432`——768×π/64 ≈ 37.7 → ceil → 38 → ×64 = 2432；
4. 输出层 lm_head 免费（tie）：`_tied_weights_keys` 声明让 transformers 在保存/加载时自动处理共享权重。

**验证方式**（动手实验 4.1 会给完整代码）：`sum(p.numel() for p in model.parameters()) / 1e6`。

## 4.6 本章小结

- MiniMind = 标准 Decoder-Only Pre-Norm Transformer，配置对齐 Qwen3；
- RoPE 用查表实现（预计算 cos/sin 表），YaRN 只拉长低频维度实现外推；
- GQA（8Q/4KV）省 KV Cache 显存；QK-Norm 稳定低精度注意力；
- SwiGLU 三矩阵 FFN；MoE 用 top-1 路由 + 负载均衡 aux loss + 死专家梯度保护；
- 64M 参数可逐项手算：词表 4.9M + 8 层 × 7.37M + 输出层 tie 免费；
- 随机初始化的 loss 基准值 $\ln V \approx 8.76$ 是训练排错的第一锚点。
