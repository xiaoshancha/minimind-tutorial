# 第 5 章 预训练：让模型学会"接龙"

> 对应代码：`trainer/train_pretrain.py`（172 行）、`trainer/trainer_utils.py`
>
> 本章目标：完整理解预训练的训练脚本——从命令行参数、数据加载、学习率调度、混合精度、梯度累积到断点续训；动手跑通第一次预训练，并学会解读 loss 曲线。学完本章，你将拥有第一个自己训练的语言模型权重。

---

## 5.1 预训练在做什么

预训练的目标（第 1 章已述）：在海量无标注文本上做**下一个 token 预测**，让模型学到：

- 语言规律（语法、搭配、惯用法）；
- 世界知识（事实、常识——只要数据里反复出现）；
- 上下文建模能力（长距离依赖）。

MiniMind 的预训练数据 `pretrain_t2t_mini.jsonl` 每行一条文本（1.2GB，含通用语料、对话整理语料、蒸馏补充语料），训练时每行文本包上 bos/eos 变成"接龙序列"。**没有人工标注、没有问答对**——这是"无监督"的含义。

## 5.2 脚本整体流程

`train_pretrain.py` 主函数分为 9 个步骤（第 109~172 行）：

```text
1. 初始化分布式环境 + 随机种子
2. 配置目录、构建模型配置、检查 checkpoint
3. 设置混合精度上下文
4. 配置可视化（swanlab/wandb）
5. 定义模型、数据集、优化器
6. 从 checkpoint 恢复状态
7. torch.compile / DDP 包装
8. 训练循环（多 epoch）
9. 清理分布式进程
```

### 5.2.1 命令行参数（第 84~107 行）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--save_dir` | `../out` | 权重保存目录 |
| `--save_weight` | `pretrain` | 权重名前缀 → `out/pretrain_768.pth` |
| `--epochs` | 2 | 训练轮数 |
| `--batch_size` | 32 | 每步样本数 |
| `--learning_rate` | 5e-4 | 初始学习率 |
| `--device` | cuda:0 / cpu | 训练设备 |
| `--dtype` | bfloat16 | 混合精度类型 |
| `--accumulation_steps` | 8 | 梯度累积 → 有效 batch = 32×8 = 256 |
| `--grad_clip` | 1.0 | 梯度裁剪 |
| `--max_seq_len` | 340 | 序列截断长度（tokens） |
| `--hidden_size` / `--num_hidden_layers` | 768 / 8 | 模型规模 |
| `--use_moe` | 0 | 是否 MoE |
| `--data_path` | `../dataset/pretrain_t2t_mini.jsonl` | 数据路径 |
| `--from_weight` | `none` | 从已有权重续训 |
| `--from_resume` | 0 | 断点自动恢复 |
| `--use_wandb` | off | 训练可视化 |
| `--use_compile` | 0 | torch.compile 加速 |

> 注意默认值之间的关系：`pretrain_t2t_mini` 数据推荐 `max_seq_len≈768`，但脚本默认 340（对应 `pretrain_t2t` 完整数据的推荐值）。**复现时按数据选值**，这个细节容易踩坑。

### 5.2.2 有效 batch size 的会计学

```python
parser.add_argument("--batch_size", type=int, default=32)
parser.add_argument("--accumulation_steps", type=int, default=8)
```

有效 batch size = 32 × 8 = **256**。这意味着：

- 显存只承担 32 条样本的前向/反向，8 步累积后更新一次；
- **学习率要与有效 batch 匹配**：5e-4 是"256 样本/更新"下的合理值。若你把 accumulation 改小，学习率应相应调小（经验法则：batch 减半 → lr 减半）。

### 5.2.3 训练循环精读（第 24~80 行）

**学习率调度**（每步更新）：

```python
lr = get_lr(epoch * iters + step, args.epochs * iters, args.learning_rate)
for param_group in optimizer.param_groups:
    param_group['lr'] = lr
```

- 全局步数 = `epoch * iters + step`，跨 epoch 连续；
- 余弦退火（第 2 章 2.3.3）：从 5e-4 平滑衰减到 5e-5。

**前向 + 损失**：

```python
with autocast_ctx:
    res = model(input_ids, labels=labels)
    loss = res.loss + res.aux_loss        # Dense 时 aux_loss=0
    loss = loss / args.accumulation_steps
scaler.scale(loss).backward()
```

- `res.loss`：交叉熵（第 4 章 4.3.8 的实现）；
- `res.aux_loss`：MoE 负载均衡损失（Dense 模型恒为 0，代码路径仍然保留——训练脚本同时支持两种架构）；
- 除以 accumulation_steps 再反传（第 2 章 2.3.1 的数学）。

**参数更新**：

```python
if step % args.accumulation_steps == 0:
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), args.grad_clip)
    scaler.step(optimizer)
    scaler.update()
    optimizer.zero_grad(set_to_none=True)
```

- 注意 `unscale_` 必须在 `clip_grad_norm_` **之前**——梯度范数计算需要真实梯度，而 fp16 下梯度是缩放过的；
- `zero_grad(set_to_none=True)`：比 `zero_()` 省内存（置 None 而非置 0，PyTorch 官方推荐）；
- 每 accumulation_steps 步一次完整更新，与 5.2.2 呼应。

**日志**（第 51~59 行）：

```python
current_loss = loss.item() * args.accumulation_steps   # 还原"未除以累积步数"的损失
current_aux_loss = res.aux_loss.item() if res.aux_loss is not None else 0.0
current_logits_loss = current_loss - current_aux_loss
eta_min = spend_time / max(step - start_step, 1) * (iters - step) // 60
Logger(f'Epoch:[{epoch+1}/{args.epochs}]({step}/{iters}), loss: {current_loss:.4f}, ...')
```

记录的是**真实 loss**（乘回 accumulation_steps），并把 MoE aux loss 拆出来单独展示——便于判断"主损失 vs 负载均衡损失"各自的表现。

**保存**（第 61~71 行）：

```python
if (step % args.save_interval == 0 or step == iters) and is_main_process():
    model.eval()
    ckp = f'{args.save_dir}/{args.save_weight}_{lm_config.hidden_size}{moe_suffix}.pth'
    raw_model = model.module if isinstance(model, DistributedDataParallel) else model
    raw_model = getattr(raw_model, '_orig_mod', raw_model)
    state_dict = raw_model.state_dict()
    torch.save({k: v.half().cpu() for k, v in state_dict.items()}, ckp)
    lm_checkpoint(lm_config, weight=args.save_weight, model=model, optimizer=optimizer,
                  scaler=scaler, epoch=epoch, step=step, wandb=wandb, save_dir='../checkpoints')
    model.train()
```

两个产物：

1. **`out/pretrain_768.pth`**：纯模型权重（fp16），供推理/SFT 加载——每次保存覆盖；
2. **`checkpoints/pretrain_768_resume.pth`**：完整快照（模型 + 优化器 + scaler + epoch/step + wandb id），供断点续训。

> `is_main_process()` 限制只有 rank 0 保存——DDP 下避免多进程写同一文件冲突。`model.eval()`/`model.train()` 切换：保存时关掉 dropout（虽然 MiniMind 默认 dropout=0，但这是规范写法）。

### 5.2.4 断点续训（第 117、140~167 行）

```python
ckp_data = lm_checkpoint(lm_config, weight=args.save_weight, save_dir='../checkpoints') if args.from_resume == 1 else None
...
if ckp_data:
    model.load_state_dict(ckp_data['model'])
    optimizer.load_state_dict(ckp_data['optimizer'])
    scaler.load_state_dict(ckp_data['scaler'])
    start_epoch, start_step = ckp_data['epoch'], ckp_data.get('step', 0)
```

恢复后的**跳过逻辑**（第 159~167 行）是本脚本最微妙的工程细节：

```python
setup_seed(42 + epoch)
indices = torch.randperm(len(train_ds)).tolist()          # 每 epoch 重新打乱
skip = start_step if (epoch == start_epoch and start_step > 0) else 0
batch_sampler = SkipBatchSampler(train_sampler or indices, args.batch_size, skip)
```

- 每 epoch 用固定种子打乱数据（`setup_seed(42 + epoch)`）→ **恢复训练时数据顺序与中断前一致**，从 step 断点精确接续，不重不漏；
- `SkipBatchSampler`（trainer_utils.py 第 134~157 行）跳过前 `skip_batches` 个 batch；
- 跨 GPU 数量恢复：`lm_checkpoint` 加载时会按 `saved_ws / current_ws` 等比调整 step（trainer_utils.py 第 110~114 行）——8 卡中断、2 卡恢复也接得上；
- 学习率曲线也连续：`get_lr(epoch * iters + step, ...)` 直接用全局步数，无需额外处理。

### 5.2.5 分布式训练（第 44~51 行 trainer_utils.py）

```python
def init_distributed_mode():
    if int(os.environ.get("RANK", -1)) == -1:
        return 0  # 非 DDP 模式（普通 python 启动）
    dist.init_process_group(backend="nccl")
    local_rank = int(os.environ["LOCAL_RANK"])
    torch.cuda.set_device(local_rank)
    return local_rank
```

- 普通 `python train_pretrain.py`：无 RANK 环境变量 → 单进程单卡；
- `torchrun --nproc_per_node N`：N 个进程各占一张卡，DDP 同步梯度；
- `DistributedSampler` + `set_epoch(epoch)`：保证各卡拿到**不重叠**的数据切片，且每 epoch 打乱方式一致；
- 注意分布式下 batch_size 是**每卡**的值：8 卡 × 32 = 256/步，数据吞吐 ×8，但 lr 是否需要调整取决于总 batch 变化。

## 5.3 第一次预训练：动手实验

### 实验 5.1：下载数据并训练

```bash
# 1) 下载 mini 数据（ModelScope 或 HuggingFace），放入 ./dataset/
#    至少需要 pretrain_t2t_mini.jsonl（1.2GB）
#    pip install modelscope
#    modelscope download --dataset gongjy/minimind_dataset pretrain_t2t_mini.jsonl --local_dir ./dataset
#    （若 CLI 失败，可从数据集页面手动下载放入 ./dataset/）

# 2) 开始训练（CPU 也可以，但会慢 20~50 倍）
cd trainer
python train_pretrain.py --max_seq_len 768
```

预期日志（前几行）：

```text
Model Params: 63.91M
Trainable Params: 63.910M
Epoch:[1/2](100/…), loss: 7.2140, logits_loss: 7.2140, aux_loss: 0.0000, lr: 0.00049880, epoch_time: 87.2min
Epoch:[1/2](200/…), loss: 6.8542, ...
...
Epoch:[2/2](…/…), loss: 4.5187, ...
```

（`…` 处为数据量相关的步数，因机器/数据而异；单卡 3090 全量约 1.2 小时/epoch，来自 README 实测。）

**loss 曲线解读**——这是预训练最重要的技能：

```text
loss
8.8 │╲  ← 起点 ≈ ln(6400) ≈ 8.76（随机初始化基准，第 4 章锚点）
    │  ╲
6.0 │    ╲     ← 快速下降段：模型迅速学会高频词、标点、句式
    │      ╲
4.5 │        ╲___← 缓慢下降段：开始学习长距离规律与知识
    │
    └────────────────────────→ step
```

- **前几百步掉得飞快**：模型先学会"最容易的规律"（常用词、标点、语法骨架），loss 从 8.76 跌到 6 以下；
- **后期变缓**：剩下的是长距离依赖与稀疏知识，每个点的收益递减；
- **理想终点**：1~2 epoch 后 loss 降至 4~5（PPL 55~150）。若 loss 卡在 6 以上不动，检查：学习率是否过大/过小、数据是否为空、mask 是否正确；
- **loss 尖峰（spike）**：突然跳高后回落，通常是某个 batch 的异常样本或学习率过大——轻微尖峰可接受，频繁尖峰需要降低 lr 或检查数据。

### 实验 5.2：测试预训练成果

```bash
# 回到项目根目录
cd ..
python eval_llm.py --weight pretrain
```

选择自动测试，观察输出。预训练模型的行为特征：

- 能"接龙"：`为什么天空是蓝色的` → 会继续输出与天空、光学相关的内容；
- 但**不会对话**：它没有见过问答格式，输出往往是一大段"续写"，而不是简洁的回答；
- 偶尔中英混杂、句子不通顺——知识量少 + 无监督训练的正常表现。

> 这正是第 6 章 SFT 存在的理由：把"会接龙"变成"会对话"。

## 5.4 常见问题排查

| 现象 | 可能原因 | 检查点 |
|------|----------|--------|
| loss 恒为 ~8.76 不降 | 数据未加载/全 padding；lr 过小 | 打印第一个 batch 的 input_ids 非全 pad；lr ≥ 1e-4 |
| loss 直接 NaN | lr 过大；fp16 溢出 | 检查 loss 是否从第一步就 NaN；换 bf16 |
| 训练速度极慢 | CPU 训练；num_workers 过小 | 核对 `torch.cuda.is_available()`；`--num_workers 8` |
| 显存不足 OOM | batch/seq_len 过大 | 减小 `--batch_size`、`--max_seq_len` 或增大 `--accumulation_steps` |
| 保存的权重无法加载 | strict=True 但权重来自不同配置 | 核对 hidden_size/num_hidden_layers/use_moe 一致 |

## 5.5 本章小结

- 预训练 = 海量文本上的 next-token 预测，无监督、无人工标注；
- 训练脚本九步走：环境 → 配置 → AMP → 可视化 → 模型数据 → 恢复 → 编译/DDP → 循环 → 清理；
- 工程四件套落地：余弦退火（带 0.1 下限）、梯度累积（有效 batch=256）、AMP（bf16 免 scaler）、梯度裁剪；
- 权重双产物：`out/` 纯权重（fp16）+ `checkpoints/` 完整快照（断点续训）；
- 断点续训靠"固定种子重排 + 跳过步数"实现精确接续，支持跨 GPU 数量恢复；
- loss 起点 ≈ ln(6400) ≈ 8.76，终点 ~4.5；快速下降→缓慢下降是正常形态。

## 5.6 思考题

1. 为什么学习率用余弦退火而不是恒定？末期保留 0.1 下限对后续 SFT 有什么意义？
2. `loss / accumulation_steps` 后 `scaler.scale(loss).backward()`——如果先 `scale` 再除以累积步数，数学上有什么区别？哪个对？
3. 断点续训时，为什么每个 epoch 必须用固定种子打乱数据？如果恢复时重新随机打乱会怎样？
4. 有效 batch 从 256 改成 64（accumulation_steps=2），学习率应如何调整？请用梯度期望的数学论证。
5. （动手）用 `--use_moe 1` 训练 500 步，对比日志中的 `aux_loss` 变化曲线与 Dense 版本的差异。
6. 为什么 `eval_llm.py` 测预训练模型时输入要用 `tokenizer.bos_token + prompt` 而不是 chat_template？请对比第 3 章 3.3 节。
